## 2. How each run works in practice

### 2a. Reddit and change requests (6:15 AM and 1:15 PM CT)

1. `git pull`. Change requests come first (playbook §5): `ArtifactData list` on collection `log`, read only. Open one when there is a request and fix it in the repo, then message HQ. No open requests: say nothing.
2. **Gmail: one search only**, `from:alerts@f5bot.com newer_than:1d` (search_threads). Then call `get_thread` on each thread with **FULL_CONTENT**. PLAIN_TEXT drops the excerpts.
   - The thread payloads are large. Hand the extraction to a subagent: it writes a JSON array to your scratchpad with id, sub, title, link, excerpt, keywords and alert_time, and reports only counts and odd cases.
   - Tell it never to write usernames, the "by" lines, and never to request any link.
3. **Parsing an alert:**
   - Each listing links through an F5Bot redirect. Decode its `u=` value with `urllib.parse.unquote` to get `https://www.reddit.com/r/<sub>/comments/<id>/<slug>/`. Never request it.
   - Strip tags, unescape entities, and remove F5Bot's own label "Keyword was found in submission title.". Some excerpts are then empty, or read "[removed]".
   - Titles arrive cut at about 80 characters with "...". Keep them as shown.
4. **Card:**
   - `ArtifactData get` on `meta`/`reddit` and note its version (7 after the Nov 23 morning run).
   - Build the new card and `set` it with `if_version`.
   - A post stays on the card while its id is in the `newer_than:1d` alerts. Keep its reply word for word, and update only the hours in its why line.
   - Hours are counted from the alert email's time, not the post's.
   - why line: `r/<sub> · <N> h old · <ask in 10 words or fewer>`, plus ` · excerpt thin` when needed. Venting, story and tips posts start the ask with `venting:`, `story:` or `tips post:`.
   - Order: help requests, freshest first, then the venting, story and tips posts, freshest first.
   - `skipped` gets title, sub and reason. `count` is the number of items.
   - Before writing, check every reply in a script: 40 to 120 words, no em dash, no link, no "Day60", an ask of 10 words or fewer, and no two replies opening with the same word.
5. `reddit/days/<YYYY-MM-DD>.md`:
   - Heading: `# Reddit today · Mon Nov 23, 2026`.
   - Then numbered `## N. <title>` items, each with the link, `**why:** ...` and the reply in a code block. End with `## Skipped`.
   - The 1:15 PM run rewrites the same day's file.
   - Commit, then push with retries: `for i in 1 2 3 4; do git push -q -u origin main && break || sleep $((2**i)); done`.
6. Message HQ about Reddit only if the Post Library write fails.

## 3. Mistakes made once, and how to avoid them

1. **Reusing Instagram Reels on Facebook without checking the end scene.** FB-onelink went into Buffer with a "Link in bio" end sticker (1b). Before reusing any image or video on Facebook, look at every slide and the last frame.
2. **Planning a Facebook post on the same day as its Instagram original.** FB-onelink was first planned for Wed, the day of IG-onelink-r2, and moved to Sat. Check the Instagram day of the same piece first.
3. **PLAIN_TEXT Gmail reads.** They lose the alert excerpts. Use FULL_CONTENT, and do it in a subagent.
4. **Whole-file reads** of `posts.md` and `library.json` after a memory cleanup filled the context. grep, then read line ranges.
5. **Republishing an artifact from a new file path** created duplicate pages: preview duplicates `AkM6PHxSAervUMuQqjaYkD` and `WpCZ4LHuDvogdJwhrcEyDH`. Leave those two alone. Republish from the same file path or the same `url`.
6. **Waiting on a create_post permission prompt** stalled the session, and its worker restarted mid-call. The new session has Buffer allowed. If a prompt ever appears, message HQ with the tool name and carry on with other work.
7. **Two inputs in one ffprobe call** errors. Probe one file per call.
8. **Messages that cross.** HQ asked for a pending-posts file minutes after the posts had already been created. Before acting on an old plan, check Buffer's actual state with `list_posts`, so nothing posts twice.
